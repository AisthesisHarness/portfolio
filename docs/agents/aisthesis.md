# Aisthesis agent workflow

<!-- aisthesis:repository-guidance:v1 -->

1. Read every applicable repository instruction and the approved feature specification before changing files. Completion criterion: every acceptance criterion in the assigned ticket is accounted for.
2. Keep the change inside the assigned ticket and feature worktree. Treat feature-topic decisions and completed dependency evidence as authoritative context.
3. Run focused verification, then the broader relevant suite when feasible. Report the exact changed-file set, each command and outcome, blockers, and acceptance evidence.
4. Leave commits, pushes, GitHub mutations, merges, deployments, and edits to protected CI/ownership/verification configuration to the Aisthesis coordinator or a human maintainer. Completion criterion: intended worktree changes and reproducible evidence are ready for coordinator inspection.
